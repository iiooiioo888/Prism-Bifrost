## 1. 概述

稜鏡持續採集公開資訊，把碎片化提及歸併成可追溯的規範事件，在訊號過閾值時告警，並輸出帶引用的結構化簡報。閉環是：

**採集 → 標準化 → 歸併 → 研判 → 交付 → 人工複核**

自動化產出進入研判層，不直接改寫事實層。

| 原則 | 工程體現 |
|---|---|
| 事實與研判分離 | 物理分表；確認前不寫事實層 |
| 探針可替換 | `Probe` 抽象；上游失效不改分析層 |
| 統計確定性優先 | `event_metrics` 只由確定性管道寫入 |
| 保守歸併 | 高、中、低三檔；中檔進人工佇列 |
| 證據可回溯 | 無引用標記為無支撐 |
| 允許不表態 | 校準置信低於 0.35 則棄權 |
| 合規內嵌 | 採集前檢查站點規則；審計僅追加 |

命名約束：神話名只用於模組、命令列、文件與溝通。資料表、欄位與日誌鍵使用中性技術命名。

| 術語 | 定義 |
|---|---|
| 原始條目 | 採集層輸出的標準化條目 |
| 提及 | 某來源對某事實的一次報導或公告 |
| 規範事件 | 由一條或多條提及支撐的事實 |
| 研判產物 | 歸併建議、敘事標籤、模型摘要、人工筆記 |
| 棄權 | 校準置信低於閾值，保留資料但退出告警與簡報 |
| 突發 | 提及速率相對基線的統計偏離 |
| 探針 | 接入某一公開來源的能力單元 |

## 2. 系統邊界

系統做：公開資訊採集、提及歸併、確定性統計、突發與優先級、帶引用的模型輔助、人在迴路複核與告警。

系統不做：突破登入牆、付費牆或驗證碼；承諾全網覆蓋；讓模型輸出直接進入事實層；全自動研判；未授權的個人資訊畫像。

合規基線：

1. 採集前檢查站點規則檔。
2. 不實作驗證碼繞過或登入態偽造。
3. 個人資訊限定目的、欄位與保留期。
4. 採集、歸併與人工操作寫入僅追加審計日誌。

## 3. 總體架構

五層：探針（福金與霧尼）→ 採集（彩虹橋基座）→ 融合（彩虹橋）→ 研判（海姆達爾）→ 交付（伊里斯）。告警通道是加拉爾號角。

第一至第二階段最小配置：Python／FastAPI、PostgreSQL 16、pgvector、Redis 7、MinIO、React／ECharts、統一模型閘道。第三階段若圖查詢變重，可加 Neo4j 唯讀副本，PostgreSQL 仍是事實層唯一寫入源。

## 4. 探針層

`Probe.fetch` 回傳 `RawItem`。原始網址必須可人工直接存取。上游時間缺失的條目進入時間缺失佇列，不參與突發檢測。備選採集在校準時再乘 0.90。

路由按優先級嘗試。首選成功標記 `live`。首選失敗且備選成功標記 `fallback`。全部失敗寫入探針失敗表，狀態為降級；長時間沒有成功則為中斷。降級必須出現在態勢面板。

第一階段只啟用零配置通道。需要登入態的社群通道保持關閉，並登記未啟用原因。

## 5. 採集層

去重分三層：網址歸一化與布隆過濾器、正文雜湊直接丟棄、相似雜湊超過 0.95 標記近似重複並保留。近似重複不作為新的歸併錨點。

失敗重試最多三次，指數退避。原始回應預設保留一百八十天，採集日誌九十天。

## 6. 融合歸併

事實層是 `canonical_event` 與 `event_mention`。研判層是歸併建議、敘事、筆記與複核動作。

```
merge_score = 0.4 * rule_score + 0.4 * semantic_score + 0.2 * entity_overlap_score
```

| 置信檔 | 條件 | 動作 |
|---|---|---|
| 高 | 得分不低於 0.85，且規則與語義同時命中 | 自動歸併並記錄連結方式 |
| 中 | 得分在 0.65 至 0.85，或達 0.85 但未雙命中 | 寫建議，不改事實層 |
| 低 | 得分低於 0.65 | 建立新規範事件 |

實體第一階段以別名表、精確匹配與邊界規則自動連結。向量相似只進入人工佇列。

確定性指標：提及量（一小時、二十四小時、七天）、來源多樣性、平台熵、六小時擴散速率、情感分布、突發得分。模型沒有 `event_metrics` 的寫權限。

## 7. 研判與告警

校準：

```
calibrated_confidence = base_band_midpoint * source_multiplier * acquisition_multiplier * bayesian_update
```

基礎頻寬：學術、語料、註冊表 0.65–0.92；網頁 0.52–0.68；社群 0.40–0.57；影片與程式碼託管 0.37–0.60。乘數只降不升：語料與註冊表 0.90、學術 0.88、網頁與社群 0.72、新聞 0.68、影片與程式碼託管 0.65、市場訊號 0.60。備選再乘 0.90。低於 0.35 棄權。

突發：

```
burst_score = (c_now - b) / (1.4826 * MAD + eps)
```

基線是過去七天同時段中位數。得分高於 3.0 進入告警候選。模型不參與檢測。

優先級預設權重 0.20、0.25、0.20、0.20、0.10，無支撐占比再減 0.05。優先級不低於 0.75 觸發高優先級告警。告警必須帶觸發規則與原始網址。

人工動作：確認、排除、歸併、拆分、標註。寫入複核動作，含操作者、理由與前後快照。

## 8. 模型

三種能力分開：分析、統計解釋、總結。模型不計算統計量，置信度不直接決定歸併。

歸併建議的支撐提及必須存在，否則標記無支撐。推測性解釋不進入高優先級告警的事實部分。簡報每條實質陳述要有事件或提及引用。合成器只用鑑別器確認過的證據。

結構解析失敗重試一次，仍失敗則標記模型輸出無效。

## 9. 交付

工作台要能篩選事件、查看提及與時間、歸併與拆分、標註、展開引用、管理棄權。態勢面板包含提及量、置信分布、突發、優先級與探針健康。簡報週期為日或週，保存生成時的證據快照。告警通道包含工作台、即時通訊、郵件與網路鉤子。

## 10. 安全與審計

角色為檢視者、分析師、管理員。敏感操作需要權杖與二次確認。刪除請求可依原始網址或作者移除提及，審計記錄保留。`audit_log` 禁止更新與刪除。

| 資料 | 保留 |
|---|---|
| 提及與事件 | 長期，可歸檔 |
| 原始回應 | 一百八十天 |
| 模型輸入輸出 | 九十天 |
| 採集日誌 | 九十天 |
| 審計日誌 | 永久 |

## 11. 到 13. 部署、路線與風險

環境分開發、預備與生產。監控涵蓋採集成功率、自動歸併量、人工拆分率、告警量、棄權比例、模型無支撐比例與佇列積壓。

第一階段交付可運行的零配置採集、提及入庫、規則與標題歸併、確定性統計，以及不靠模型的人工基準簡報。第二階段擴來源、圖譜與模型建議。第三階段完成校準、突發評分、鑑別器與合成器分離、工作台與告警。

主要風險：探針失效、合規越界、誤合併、幻覺進入研判、訊號價值未證明、突發誤報、模型成本失控。緩解分別是備選路徑與健康度、採集前拒絕、三檔與可回滾提及、引用閘門、第一階段驗收、可調閾值、分級呼叫與預算告警。

命令列見專案說明。核心閾值的預設值在 `config/prism.yaml`：自動歸併 0.85、人工複核 0.65、棄權 0.35、突發 3.0、告警 0.75。
