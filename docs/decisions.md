# 設計結論

這 62 條是目前已形成的判斷，直接作為設計基線。後續變更若偏離其中任一條，必須在本檔變更記錄說明理由，並經專案負責人確認。

實作補法若與本檔衝突，以這 62 條為準。尚未被結論寫死的縫隙仍列在附錄，且附錄不得推翻正文。

提及校準的棄權門檻仍是 0.35，只作用於規範事件。雙11結論的棄權是分級輸出，兩者並存。

## 一、項目定位

1. 系統是感知與研判輔助，不是全自動真相機。最終判斷保留人工權威，自動化只做排序、解釋和假設生成。
2. 系統不承諾全網覆蓋。覆蓋廣度是漸進目標，不是產品承諾；名字與對外表述都避免「全」「實時」「全自動」。
3. 系統的核心價值在 L3–L4，不在 L1–L2。採集可以租用，歸併與研判必須自建。
4. 合規是設計約束，不是事後補丁。不突破登入牆、付費牆、驗證碼；站點規則檔是採集前第一道判斷。

## 二、架構

5. 五層流水線保持不變：探針層 → 採集標準化 → 融合歸併 → 研判告警 → 交付。
6. 探針層是可替換的能力層，不是封裝層。必須在探針外面包一層自建抽象接口，更換上游工具不影響 L3 以上邏輯。
7. 事實層與研判層物理分表。任何自動化產出不直接改寫事實層關聯。
8. 統計量由確定性代碼計算，模型只解釋。事件指標表只允許確定性管道寫入。
9. 允許不表態。校準置信度低於閾值的條目保留在庫，但排除出告警與簡報合成。
10. 神話命名只用於命名與溝通層。資料庫表名、API 欄位、日誌鍵名使用中性技術命名。

## 三、數據模型

11. 雙層資料模型是基石：`canonical_event` 表示現實事件，`event_mention` 表示來源的一次提及；提及永遠保留，不因歸併而刪除或改寫。
12. 研判層與事實層物理隔離。歸併建議、敘事標籤、分析筆記、複核動作單獨存放，人工確認前不影響事實層。
13. 每個採集條目必須攜帶真實源網址、真實上游時間戳、採集模式標記。採集模式區分正常採集與備選採集。
14. 提及的採集模式為備選時，在可信度校準中降權。降權係數可配置，預設 0.90。

## 四、採集層

15. 探針採用「首選 + 備選」有序路由。首選失敗切備選，全部失敗標記通道降級，降級狀態必須顯式展示，不允許靜默歸零。
16. 第一階段只啟用零配置通道。社群通道第二階段按需解鎖，且必須登記登入態維護責任人。
17. 來源健康度是一等公民。每個通道跟蹤最近成功時間、連續失敗次數、備選比例、平均延遲、狀態。
18. 雙11場景下需要劣化速率指標。失敗率加速上升時提前啟用備選，而不是等到完全失效。

## 五、歸併層

19. 歸併採用三檔置信度：高置信自動歸併，中置信進入人工佇列不自動歸併，低置信建立新事件。
20. 誤合併比漏合併更危險。第一版寧可事件稍多，也不能把不同事實靜默合併。
21. 模型歸併建議不直接觸發自動歸併。只有規則高置信或人工確認才寫事實層關聯。
22. 實體連結第一階段不追求全自動消歧。別名表、規則匹配與向量相似度進入人工確認佇列。
23. 事件圖譜第二階段引入。PostgreSQL 遞迴查詢起步，第三階段可加圖資料庫唯讀副本，但 PostgreSQL 仍是事實層唯一寫入源。

## 六、研判層

24. 信源可信度兩層校準：來源類型基礎頻寬 × 來源可信度乘數（只降不升）× 採集模式修正 × 貝氏更新。
25. 校準置信度低於 0.35 進入棄權。保留數據，但排除出告警排序與簡報合成。
26. 突發檢測用穩健統計（中位數絕對偏差），不用均值；模型不參與突發檢測，只解釋驅動因素。
27. 優先級評分是加權和，權重可配置。第一階段不引入機器學習模型。
28. 告警必須攜帶觸發規則和原始訊號網址。不允許黑箱告警。
29. 人工複核的每次操作寫入僅追加日誌。用於校準閾值、更新來源可信度、評估模型建議採納率。

## 七、模型整合

30. 模型三能力分離：分析、統計解釋、總結。
31. 模型不直接計算任何統計量，也不直接生成任何貨幣金額。數字必須來自確定性管道，模型只能引用。
32. 三層幻覺抑制：結構化輸出約束 → 引用可驗證性 → 鑑別器與合成器分離。
33. 無引用支撐的陳述標記為無支撐，不進入高優先級輸出。
34. 簡報由模板約束，不是自由撰寫；每條實質性陳述攜帶事件或提及引用；輸出標註「模型輔助，待人工確認」。
35. 模型透過統一閘道呼叫，業務代碼不綁定具體廠商；成本控制靠批次、快取、分級呼叫、限流、預算告警。

## 八、場景承載

36. 場景是配置，不是功能。新場景的成本是配置與驗證，不是另開一套流水線。
37. 每個場景由五維度定義：關注對象、訊號域、觸發條件、交付終點、時間敏感度。
38. 場景配置掛在既有流水線上，不新增流水線；共用探針接口、事實層模型、統計管道、校準機制、複核工作台。
39. 場景之間隔離的是：場景配置、關注實體與別名、觸發規則與權重、告警通道與頻率、資料保留與合規登記。
40. 每個場景上線前必經小樣本驗證。跑 2–3 天資料，人工複核，確認訊號存在、歸併粒度合理，再校準參數上線。

## 九、雙11場景的結構性結論

41. 雙11場景的錨點是標準化 SKU，不是事件。同一商品在各平台的頁面不是同一事件的多條提及，而是同一決策對象的多個可選方案。
42. 規則引擎不是加法陣列，是帶層級、互斥和優先級的約束求解器。必須建模單品級 → 店鋪級 → 平台級 → 紅包 → 國補。
43. 國補順序是硬約束，不是可配置項。國補永遠最後一道，計算基數是前面所有抵扣後的實付價；錯誤順序應被規則校驗拒絕。
44. 價格信號必須帶可比性元數據，包括 SKU 匹配置信度、價格基準（遊客態／登入態）、有效期、價保口徑。裸價格數字不足以支撐決策。
45. SKU 匹配需要置信度分檔，不是二元匹配或不匹配；比價結論的可信度上限受 SKU 匹配置信度約束。
46. 價保不是天數，是帶排除條款的布爾判斷。頁面標價下降是唯一直接觸發維度；國補、平台券、紅包、百億補貼通常不納入價保。
47. 模型在比價場景的權限邊界必須由結構性約束定義，不能靠提示詞提醒。價格數字生成權歸規則引擎，「最便宜」判斷權歸多準則排序引擎。
48. 棄權需要分級，不是二元。輸出分解為可確定執行的結論、需用戶確認的前置條件、不確定的風險項、被禁止輸出的聲明。
49. 時間敏感度要求分離快慢兩條路徑。快速路徑事件驅動、秒級到分鐘級，走規則引擎與決策合成器；慢速路徑定時批處理、小時級到天級，維護基線與健康度。
50. 歷史價格基線需要前置積累。場景啟動前至少 2 週開始採集日常價格；基線不足時，結論必須顯式標註置信度降低。
51. 「當前最低價」不等於「最優決策」。價保、庫存可靠性、售後都是決策維度；輸出應是帶理由的排序，不是絕對最低價標籤。

## 十、優先級與實施

52. P0：規則引擎的層級、互斥與順序建模；模型禁止生成貨幣金額；結構化棄權。
53. P1：SKU 匹配置信度分檔；價格基準可比性標註；價保排除條款布爾建模。
54. P2：快慢路徑分離；採集劣化速率感知。
55. P3：歷史價格基線；多準則排序替代標量評分。
56. 第一階段驗收仍綁定「歸併後發現單篇漏掉的事件」。雙11場景的驗收改為在預售、開售、衝刺三個節點對 N 個 SKU 輸出可複核結論，並事後驗證準確率。
57. 最小團隊 3–4 人，人工複核不可省略。項目負責人同時是第一批用戶和驗收判斷者。

## 十一、風險與邊界

58. 探針通道失效是常態，不是異常。備選路徑和健康度巡檢是日常運維項。
59. 合規風險在電商場景高於通用公開資訊研判。登入態復用、瀏覽器指紋模擬、風控對抗的邊界必須逐場景登記，不能預設公開可見即可採。
60. 模型幻覺進入研判是可控風險。靠結構約束、引用校驗、角色分離控制；模型輸出永不直接進事實層。
61. 信號價值未被證明是項目最大風險。第一階段驗收標準直接綁定人工複核後是否發現有價值的事件，不達標就停止擴展。
62. 系統的複雜度收斂在流水線本身，場景的複雜度收斂在配置裡。任何讓場景邏輯侵入流水線核心的設計，都應被拒絕。

## 附錄：尚未寫死的實作補法

閾值仍以設定檔為準。這些補法只填說明書沒有寫死的縫，不得推翻上面 62 條。

| 題目 | 決定 |
|---|---|
| 分數達 0.85 但規則或語義缺一 | 落入人工佇列，不自動歸併 |
| 規則與語義都滿分且實體重疊為 0 | 得分 0.80，屬中檔 |
| 新聞的基礎頻寬 | 沿用網頁頻寬，乘數仍用 0.68 |
| 市場訊號的基礎頻寬 | 沿用社群頻寬，乘數仍用 0.60 |
| 第一階段貝氏更新 | 乘數恆為 1 |
| 突發基線 | 過去七個對齊的一小時窗口，缺資料記 0 |
| 突發歸一化 | `clamp(score / 3, 0, 1)` |
| 優先級的來源多樣性 | 優先取二十四小時內未棄權提及 |
| 近似重複 | 保留並掛到原事件，不另開規範事件，不額外乘進校準公式 |
| 語義分數 | 正文的字元二元組餘弦；嵌入模型接上後只替換這個函式 |
| 語義命中初值 | 0.60，標成待校準 |
| 時間缺失 | 入 `timestamp_gap_queue`，不參與突發計數 |
| 登入態探針 | 只回報未啟用，不實作採集 |
| 號角測試 | 乾跑，不向外部網址送出 |
| 雙11排序權重 | 實付 0.40、價保 0.25、庫存可靠性 0.20、售後可靠度 0.15，可在場景配置調整，權重之和必須為 1 |
| SKU 分檔初值 | 高檔 ≥ 0.85，中檔 ≥ 0.65，其餘為低檔 |
| 劣化提前門檻 | 前後半段失敗率之差 ≥ 0.25，且樣本至少 4 筆 |
| 售後維度 | 以 0 到 1 的可靠度計入排序，不由模型生成金額 |
| 登入態標價 | 可以登記頁面要求登入，不得寫入登入態價格數字 |
